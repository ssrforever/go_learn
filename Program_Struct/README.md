在Go语言中，返回函数中局部变量的地址也是安全的
```
var p = f()

func f() *int {
    v := 1
    return &v
}

```
调用f函数时创建局部变量v，在局部变量地址被返回之后依然有效，因为指针p依然引用这个变量。

详细解释：Go 的逃逸分析（Escaping Analysis）
这段代码在 C 或 C++ 等语言中，会是一个严重的错误，因为它返回了一个指向局部变量（栈上变量）的指针。一旦函数 f() 执行完毕，变量 v 所在的栈帧就会被销毁，导致返回的指针 p 变成一个悬空指针（Dangling Pointer）。

然而，Go 语言的编译器和运行时系统避免了这个问题，因为它使用了称为**逃逸分析（Escaping Analysis）**的机制：

编译器分析： Go 编译器在编译时会分析变量的生命周期。

生命周期延伸： 编译器看到函数 f() 返回了局部变量 v 的地址（&v）。它知道，如果将 v 留在栈上，它将在函数返回后失效。

自动分配到堆（Heap）： 编译器会智能地判断，变量 v 的生命周期逃逸（Escape）出了函数 f 的作用域。因此，编译器会默默地将变量 v 的存储位置从**栈（Stack）自动提升到堆（Heap）**上。

安全返回： 函数 f() 返回时，v 的值存储在堆上，即使 f() 结束，堆上的内存也不会被立即释放。
